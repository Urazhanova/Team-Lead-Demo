## ФИЛОСОФИЯ РАЗРАБОТКИ

**Принцип:** Каждая итерация = работающий продукт, который можно протестировать

**Подход:** 
- ✅ Сначала делаем простую рабочую версию

- ✅ Тестируем после каждого этапа
- ✅ Можно остановиться на любом этапе и иметь работающий урок

## ЭТАП 1: MVP - ЛИНЕЙНАЯ ЦЕПОЧКА (1-2 дня)

### Цель
Сделать простейший работающий прототип: 3-5 сообщений подряд без ветвлений

### Что входит

**1.1. Базовая механика сообщений**
- Сообщения появляются по таймеру
- Только информационные сообщения (не требуют ответа)
- Фиксированная последовательность

**1.2. Простейший сценарий (5 минут игры)**

```
[09:00] Briefing
↓
[09:03] Денис: "Доброе утро! Начинаю работу над API"
↓
[09:05] Игорь: "Запускаю регресс-тестирование"
↓
[09:10] Мария: "Работаю из дома сегодня"
↓
[09:15] Виктор: "Как дела? Всё по плану?"
↓
[09:20] Финал: "Поздравляем! Ты прошел демо-версию"
```

**1.3. Таймер**
- Реальное время: 5 минут
- Игровое время: 9:00 → 9:20 (20 минут)
- Соотношение: 1 реал. мин = 4 игр. мин

**1.4. Энергия**
- Статичная шкала (не меняется)
- Просто визуализация: 100%

### Код (псевдокод)

```javascript
const messages = [
  { time: 0, gameTime: "09:00", from: "system", text: "День начался!", channel: "system" },
  { time: 3, gameTime: "09:03", from: "denis", text: "Доброе утро!", channel: "DM_denis" },
  { time: 5, gameTime: "09:05", from: "igor", text: "Запускаю тесты", channel: "dev-team" },
  { time: 10, gameTime: "09:10", from: "maria", text: "Работаю из дома", channel: "DM_maria" },
  { time: 15, gameTime: "09:15", from: "viktor", text: "Как дела?", channel: "DM_viktor" },
];

let elapsedTime = 0;

setInterval(() => {
  elapsedTime++;
  updateGameTime(elapsedTime);
  checkMessages(elapsedTime);
}, 1000); // каждую секунду

function checkMessages(time) {
  const pending = messages.filter(m => m.time === time && !m.shown);
  pending.forEach(showMessage);
}
```

**Критерий готовности:**
✅ Сообщения появляются по расписанию
✅ Таймер идёт и показывает игровое время
✅ Можно "прожить" 5 минут от начала до конца
✅ Нет багов, нет вылетов

**Что тестируем:**
- Работает ли таймер?
- Появляются ли сообщения вовремя?
- Понятен ли интерфейс?

## ЭТАП 2: ДОБАВЛЯЕМ ВЫБОРЫ (2-3 дня)

### Цель
Добавить интерактивность - игрок может выбирать ответы

### Что добавляем

**2.1. Механика выборов**
- Сообщение-запрос с 2-3 вариантами ответа
- Кнопки для выбора
- После выбора - последствие

**2.2. Простой сценарий с выбором (10 минут игры)**

```
[09:00] Briefing
↓
[09:03] Денис: "Доброе утро! Начинаю работу"
↓
[09:10] Денис: "Застрял с API. Поможешь?" 
        → ВЫБОР:
        [A] Помочь (5 мин)
        [B] Делегировать Марии (2 мин)
↓
[Зависит от выбора A или B]

ЕСЛИ выбрал [A]:
[09:15] Денис: "Спасибо! Разобрался!"

ЕСЛИ выбрал [B]:
[09:12] Денис: "Окей, спрошу у Марии"
[09:20] Мария: "Помогла Денису"

↓
[09:25] Виктор: "Как команда?"
↓
[09:30] Финал с результатами
```

**2.3. Система последствий**
```javascript
const choices = {
  "denis_help": {
    options: [
      {
        id: "help_myself",
        text: "Помогу сам",
        cost_time: 5,
        cost_energy: 10,
        consequences: [
          { delay: 5, from: "denis", text: "Спасибо! Разобрался!", mood: "happy" }
        ]
      },
      {
        id: "delegate_maria",
        text: "Попроси Марию",
        cost_time: 2,
        cost_energy: 5,
        consequences: [
          { delay: 2, from: "denis", text: "Окей, спрошу" },
          { delay: 10, from: "maria", text: "Помогла Денису", mood: "neutral" }
        ]
      }
    ]
  }
};
```

**2.4. Энергия (рабочая)**
- Начало: 100%
- Каждый выбор тратит энергию
- Визуализация изменяется

**2.5. Простая концовка**
```
Ты закончил день!

Энергия: [оставшаяся]%
Денис: [доволен/нейтрален]

[Начать заново] [Продолжить к следующему уроку]
```

**Критерий готовности:**
✅ Можно выбрать вариант ответа
✅ Выбор влияет на дальнейшие сообщения
✅ Энергия уменьшается при выборах
✅ Есть простая концовка с результатами

**Что тестируем:**
- Работают ли кнопки выбора?
- Приходят ли правильные последствия?
- Меняется ли энергия?
- Понятно ли, что выбор влияет на результат?

## ЭТАП 3: РАСШИРЯЕМ СЦЕНАРИЙ (3-4 дня)

### Цель
Добавить больше контента - несколько цепочек взаимодействий

### Что добавляем

**3.1. Больше персонажей**
- Денис (2-3 взаимодействия)
- Мария (2 взаимодействия)
- Игорь (1-2 взаимодействия)
- Виктор (1 взаимодействие)

**3.2. Сценарий на 20 минут игры**
```
9:00 - 9:30: Утро (4-5 взаимодействий)
9:30 - 10:00: Появление проблем (3-4 взаимодействия)
10:00 - 10:30: Разрешение (2-3 взаимодействия)
10:30: Финал
```

**3.3. Параллельные события**
- Несколько персонажей могут писать одновременно
- Игрок выбирает, кому отвечать первому

**Пример:**
```
[09:10] Денис: "Помоги с API?"
[09:12] Игорь: "Нашел баг"
[09:15] Мария: "Нужна консультация"

→ Все 3 сообщения висят без ответа
→ Игрок решает, кому отвечать
→ Неотвеченные ждут
```

**3.4. Система настроений**
- У каждого персонажа есть состояние
- Влияние от действий игрока
- Визуализация: 😊😐😔

**3.5. Расширенная концовка**
```
РЕЗУЛЬТАТЫ ДНЯ

✅ Денис: 😊 Доволен (ты помог)
⚠️ Мария: 😐 Перегружена (много делегировал)
✅ Игорь: 😊 Справился сам

Твоя энергия: 65%

Оценка: ⭐⭐ Хорошо!

💡 Совет: Можно больше делегировать Игорю

[Играть снова] [Следующий урок]
```

**Критерий готовности:**
✅ 20 минут игрового контента
✅ 8-10 точек выбора
✅ Настроения персонажей меняются
✅ Концовка показывает детальные результаты

**Что тестируем:**
- Интересно ли играть 20 минут?
- Понятны ли последствия выборов?
- Хочется ли переиграть с другой стратегией?

## ЭТАП 4: ДОБАВЛЯЕМ ДАВЛЕНИЕ (2-3 дня)

### Цель
Добавить механики, создающие напряжение и срочность

### Что добавляем

**4.1. Эскалации**
Если игрок не отвечает → ситуация ухудшается

**Пример:**
```
[09:10] Денис: "Помоги?"
        Статус: 🟡 Ожидает

[Прошло 5 минут без ответа]

[09:15] Денис: "Алекс, ты тут?"
        Статус: 🟡 Ожидает (нетерпеливо)

[Прошло еще 10 минут]

[09:25] Денис: "Ладно, попробую сам..."
        Статус: 🔴 Риск

[Прошло еще 15 минут]

[09:40] Денис: "Сделал, но тесты не проходят 😔"
        Статус: 🔴 Провалено
        Последствия: +30 минут работы на исправление
```

**4.2. Типы сообщений**
- 📨 INFO (можно пропустить)
- ❓ REQUEST (нужно ответить)
- 🔥 ALERT (срочно!)

**4.3. Алерты**
- Визуально выделяются (красный цвет)
- Звуковой сигнал (опционально)
- Нельзя игнорировать долго

**4.4. Обед-выбор**
```
[12:00] АВТОМАТИЧЕСКАЯ ПАУЗА

Обеденный перерыв. Как проведешь?

[A] Полноценный обед (30 мин)
    → +25% энергии

[B] Быстрый перекус (15 мин)
    → +15% энергии

[C] Пропустить (0 мин)
    → 0% энергии
    → Штраф: все действия после обеда +50% времени
```

**4.5. Сценарий на 30 минут**
```
9:00 - 10:00: Утро (спокойно)
10:00 - 12:00: Нарастание (больше запросов)
12:00: ОБЕД (выбор)
12:30 - 14:00: После обеда (зависит от выбора)
14:00 - 15:00: Пиковый хаос (всё одновременно)
15:00: Финал
```

**Критерий готовности:**
✅ Неотвеченные сообщения эскалируются
✅ Есть алерты (визуально отличаются)
✅ Обед - важный выбор
✅ Чувствуется нарастание напряжения

**Что тестируем:**
- Чувствуется ли давление времени?
- Страшно ли игнорировать сообщения?
- Хочется ли пообедать или пропустить?

**5.4. Множественные концовки**
- ⭐⭐⭐ Идеальный баланс (90-100)
- ⭐⭐ Героический менеджер (70-89)
- ⭐ Хаотичный новичок (50-69)

  - Выгорание
  - Катастрофа
  - Провал баланса

**5.5. Система скоринга**
```javascript
const score = {
  critical_tasks: 0,      // max 30
  important_tasks: 0,     // max 25
  team_mood: 0,          // max 20
  player_energy: 0,      // max 15
  work_life_balance: 0   // max 10
};

function calculateFinalScore() {
  const total = Object.values(score).reduce((a, b) => a + b, 0);
  
  if (total >= 90) return "perfect";
  if (total >= 70) return "good";
  if (total >= 50) return "survived";
  return "game_over";
}
```

**Критерий готовности:**
✅ Полные 12 минут контента
✅ Все персонажи и ситуации из сценария
✅ Все концовки реализованы
✅ Система скоринга работает
✅ Можно переиграть с разными стратегиями

**Что тестируем:**
- Можно ли получить все 4 концовки?
- Баланс сложности (не слишком легко/сложно?)
- Реиграбельность (хочется ли попробовать по-другому?)

## КОНТРОЛЬНЫЕ ТОЧКИ

После каждого этапа:

**DEMO:**
- Показать работающую версию
- Получить фидбек от Ирины

**GO/NO-GO решение:**
- ✅ GO → продолжаем к следующему этапу
- ⏸️ ITERATE → дорабатываем текущий этап
- ❌ STOP → останавливаемся, есть критичные проблемы

**АДАПТАЦИЯ:**
- Если времени меньше → можно остановиться на этапе 3-4
- Если нужно быстрее → можно совместить этапы 1+2
- Если всё идёт хорошо → можно добавить доп. контент
